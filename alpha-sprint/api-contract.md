# Alpha API/数据契约草案

> 当前仓库还没有后端实现。本文件把上次设计书中的边界转为协作契约，供前后端实现前评审；接口状态不能写成已联调。

## 统一约定

- 基础路径：`/api/v1`（拟议）。
- 认证：`Authorization: Bearer <token>`（拟议）。
- 时间：ISO-8601，明确时区；政策日期和用户提醒日期分开。
- 错误：`{ "code": "稳定错误码", "message": "用户可理解的说明", "trace_id": "可选" }`。
- Agent 不直接访问数据库，只能通过受控工具取得经过权限过滤的证据包。

## 接口草案

| 方法 | 路径 | 用途 | 权限 | 状态 |
|---|---|---|---|---|
| GET | `/policies` | 按事务、画像和关键词检索已发布政策 | 登录用户 | 设计草案 |
| GET | `/policies/{id}` | 查看政策版本、来源和适用对象 | 登录用户 | 设计草案 |
| POST | `/conversations/{id}/messages` | 提交问题并返回结构化回答 | 登录用户 | 设计草案 |
| POST | `/checklists` | 用户确认后生成材料清单 | 登录用户 | 设计草案 |
| PATCH | `/checklists/{id}/items/{itemId}` | 更新清单项状态 | 清单所有者 | 设计草案 |
| POST | `/reminders` | 创建个人提醒，不等于官方通知 | 登录用户 | 设计草案 |
| GET | `/me/profile` | 读取办事画像 | 本人 | 设计草案 |
| PATCH | `/me/profile` | 更新办事画像 | 本人 | 设计草案 |
| POST | `/admin/policies/drafts` | 创建政策草稿 | 录入员 | 设计草案 |
| POST | `/admin/policies/{id}/verify` | 记录复核结果 | 核验员 | 设计草案 |
| POST | `/admin/policies/{id}/publish` | 发布新版本 | 核验员/管理员 | 设计草案 |

## 关键不变量

1. 只有 `published` 且未过期的政策版本可作为确定性回答证据。
2. 每个回答引用至少包含 `policy_version_id`、原文片段和核验时间。
3. 用户只能读取、修改和删除自己的画像、清单、提醒与反馈。
4. 发布新版本不能静默修改历史回答的引用。
5. 检索无证据、证据冲突、模型超时或政策过期时，必须返回可解释的降级状态。
